# UI language

The app is fully bilingual (English / Greek) behind a header toggle. Every
user-visible string goes through the message table.

> Superseded: this file used to document a deliberate mix — English for
> structural chrome, Greek for anything said *to* the reader. That split existed
> because there was no language switch. There is one now, so the rule is simply
> "translate everything".

## How it works

The active language lives in a first-party `locale` cookie, so the server and
the client render the same thing and there is no hydration mismatch.

| Context | Import | Usage |
| --- | --- | --- |
| Server component | `getServerT()` from `@/lib/i18n-server` | `const t = await getServerT()` |
| Client component | `useT()` from `@/components/LanguageProvider` | `const t = useT()` |
| Passed down | `TFunc` from `@/lib/i18n` | `function Panel({ t }: { t: TFunc })` |

Both read one flat table in `lib/i18n.ts`. Keys are namespaced with dots
(`nav.upcoming`, `proj.eu.title`, `hist.legend`) and interpolate `{name}`
placeholders:

```tsx
t("proj.eu.desc", { sims: proj.sims.toLocaleString(), n: proj.matches_remaining })
```

A missing key falls back to English, then to the raw key — so a half-translated
build degrades to English rather than rendering blank.

## Adding UI

1. Add the key to **both** `en` and `el` in `lib/i18n.ts`.
2. Never concatenate translated fragments — word order differs between the two
   languages. Use one key with placeholders for the whole sentence.
3. Leave as-is in both languages: team names, market names (GG, NG, Over 2.5),
   numbers and dates.
4. Content generated by the backend (the LLM match analysis, model notes such as
   the Greek play-off caveat) is produced in one language and passed through — it
   is not part of this table.
